# 项目总览

## 一句话定位

腾讯频道（QQ 频道）单频道的**管理员 Web 后台**：把频道内容与成员的日常巡查、违规处置、数据统计从「人工翻帖子」变成「系统自动爬取 + 批量处置 + 全程留痕」。

目标频道固定为「米游全肯定基地」（`guild_id = 82203161765285899`），不做多频道抽象。

## 需求来源

完整需求规格见仓库外的 `../PROJECT_PROMPT.md`（约 22KB）。该文档定义了最初的四大模块、数据库设计、爬取引擎设计和前端页面设计，是本项目的设计基线。理解「为什么这样设计」时应先读它。

## 模块边界

### 做什么

- **数据采集**：通过 `tencent-channel-cli` 调用腾讯频道接口，增量抓取帖子、评论、回复、成员，落库后永不物理删除（删除只置 `status = 'deleted'`）。
- **内容管理**：帖子 / 评论 / 回复的浏览、检索、筛选，以及违规标记。
- **违规处置**：删帖、移帖、禁言、踢人等动作，附带通知推送与审计快照。
- **成员管理**：成员档案、加入时间、活跃历史、自定义标签。
- **统计分析**：DAU / WAU / MAU、内容与互动趋势、Top 发帖评论榜。
- **自动化**：按作者 ID 的自动处置规则、定时增量爬取、定时成员同步。
- **账号体系**：平台用户注册与管理员审批、多管理员 CLI 身份轮转。

### 不做什么

- 不做多频道（`GUILD_ID` 是全局单值）。
- 不直接调用腾讯接口，所有外部数据都经 `tencent-channel-cli` 中转。
- 不物理删除业务数据，违规记录与操作日志均只增不改。
- 不做实时消息推送，互动数据靠定时任务轮询。

## 三个容易混淆的概念

接手时最容易搞错的是这三组概念，代码里到处都在用：

| 概念 | 说明 |
|------|------|
| **Feed / Comment / Reply** | 帖子 / 顶层评论 / 对评论的回复。`Reply` 永远挂在一个 `Comment` 下，没有「回复的回复」——层中层在数据上用 `target_reply_id` + `target_user` 表达，仍归属同一个顶层 `Comment`。 |
| **平台用户 vs 管理员身份** | `PlatformUser` 是登录后台的人（`role`: `admin` / `operator`）；`AdminIdentity` 是腾讯频道侧的执行身份（一个昵称 + 一份加密 token）。一个平台用户可以对应一个管理员身份，处置动作实际是用某个管理员身份的 CLI 凭据去执行的。 |
| **评论 vs 回复（前端口径）** | 在 CLI 层和数据库层 `Comment` / `Reply` 是两张表；但**前端统一称「评论」**，不出现「回复」字样，避免使用者混淆层级。改前端文案时保持这个口径。 |

## 当前状态

### 功能完成度

四大模块（数据浏览、违规处置、成员管理、统计分析）均已上线可用，另有爬取管理和系统设置两个支撑模块。功能层面的主要缺口见 [KNOWN-ISSUES.md](KNOWN-ISSUES.md)。

### 生产数据规模

以下为 2026-09-17 生产库实际值，可作为性能与容量判断的基准：

| 表 | 行数 | 备注 |
|----|------|------|
| `feeds` | 47,955 | 帖子 |
| `comments` | 87,205 | 其中 320 条为已删除状态 |
| `replies` | 55,904 | 其中 83 条为已删除状态 |
| `members` | 2,790 | 频道成员 |
| `crawl_tasks` | 90,795 | **持续增长且无清理机制**，见技术债 |
| `violations` | 31 | 违规处置记录 |
| `platform_users` / `admin_identities` | 12 / 12 | 后台账号与 CLI 执行身份 |
| `auto_rules` | 2 | 自动处置规则 |

数据库总大小约 336 MB。

### 数据可信度提示

存量数据来自多次脚本迭代，早期爬取存在字段缺失与计数不准的历史包袱（例如 `feeds.content` 有相当比例的 NULL，依赖 `scripts/fix_details.cjs` 之类的补数脚本回填）。**基于旧数据做统计时要标注数据来源与覆盖范围**，不要把统计口径当作业务真值。

## 相关术语

| 术语 | 含义 |
|------|------|
| light 爬取 | 每分钟执行的轻量增量爬取，只扫最近几页 |
| deep 爬取 | 每天 3:30 执行的全量增量爬取，翻遍所有帖子并对账评论 |
| full 爬取 | 全量重建，只能手动触发，会阻塞其它所有任务 |
| members 爬取 | 每 10 分钟同步一次成员列表 |
| 对账（reconcile） | 用频道侧声明的 `comment_count` 与实际入库的评论+回复数比对，不一致就补拉 |
| 管理员身份轮转 | 多个 CLI 身份轮流使用，规避单账号限流 |
