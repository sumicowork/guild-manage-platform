# archive — 历史文件留档

这里存放的是项目早期方案的产物。它们与当前的运行方式无关，留在仓库根目录会误导接手者，因此集中到此处留档备查（文件内容未做修改）。

| 文件 | 原始用途 | 为什么留档而不删除 |
|------|---------|------------------|
| `DEPLOY.md` | 最初的服务器部署指南 | 记录了早期方案的技术选择：apt 安装 PostgreSQL、服务器上 `npm ci` + `next build`、PM2 以 `npm start` 启动、Nginx 反代 3000 端口。这些与当前方案（Docker 化数据库、构建产物分发、standalone 单进程启动、3003 端口）完全不同，作为演进记录保留 |
| `start.js` | 容器/一体形态的统一启动入口 | 依次执行「等待数据库就绪 → `prisma db push` → 判断是否需导入历史 JSON → 启动服务」。它依赖的是应用源码与 `node_modules` 同时在场且由 Node 直接启动 `next`，与 standalone 产物的启动路径不兼容 |
| `Dockerfile` | 两阶段容器镜像构建 | 描述了在容器内完成 `npm ci` + `prisma generate` + `next build` 的完整流程，可作为将来重建容器化方案时的参考起点 |

## 使用提示

- 这三个文件**不参与当前构建与运行**，任何路径都不会引用它们。
- 如果确实要回到容器化方案，`Dockerfile` 的依赖安装顺序（先 `package.json` 再 `src`，以利用层缓存）与 `start.js` 的启动前置检查（等待数据库、按需导入历史数据）仍然有参考价值。
- 部署相关的现行做法不在本仓库文档范围内。
